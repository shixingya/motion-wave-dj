# MOTION WAVE DJ 产品需求文档（PRD）

版本：v1.0
状态：已实现并上线
在线地址：<https://shixingya.github.io/motion-wave-dj/>

## 1. 背景与目标

### 1.1 背景

体感类节奏游戏长期依赖专用外设（跳舞毯、体感主机）或移动端 App，门槛高、普及率低。与此同时，浏览器能力已完全成熟：WebGL 可承载高质量 3D 渲染，getUserMedia + 端侧姿态识别模型可做到无服务器的人体动作识别，Web Audio 可程序化合成全部音效。三者结合意味着"摄像头即手柄、浏览器即主机"的体感游戏可以做到零安装、零素材、零后端。

MOTION WAVE DJ 由此诞生：一款打开链接就能玩的 3D 夜店体感节奏游戏，玩家的身体就是控制器和乐器。

### 1.2 目标用户（全年龄）

- **核心用户**：喜欢音乐节奏游戏的普通玩家（8~40 岁），在客厅/宿舍用笔记本即可游玩
- **家庭场景**：祖孙同乐——动作简单直观（挥手、下蹲），无摄像头时键盘降级保证人人可玩
- **聚会场景**：双人同屏对战/共演，作为派对破冰节目
- **轻度健身**：跟拍挥臂与下蹲动作自带轻量运动属性

设计原则：大字号中文文案、高对比霓虹配色、无生僻操作概念、所有提示可读可懂。

### 1.3 产品目标

1. 首次进入到开始游玩不超过 3 次点击（选人数 → 选模式 → 引导弹窗确认）
2. 动作识别延迟感知低于 100ms（保持式判定 + 音频时钟对齐）
3. 主流笔记本（集成显卡）稳定 60fps 渲染，低端设备自动降级不卡死
4. 零素材、零后端、零构建：仓库即全部产物，静态托管即可上线

## 2. 核心概念

- **节拍目标**：DJ 模式下背景曲每拍生成一个目标动作（左臂/右臂/双手/下蹲），玩家在判定窗口内完成即得分
- **保持式判定**：举手 = 手腕高于同侧肩约一掌以上；下蹲 = 髋膝垂直间距明显压缩并连续 3 帧确认，避免误触
- **双时钟对齐**：音乐节拍由 AudioContext 时钟精确排程（lookahead 模式），判定用同一时钟，视觉脉冲由渲染循环消费排程队列，保证"看、听、判"三者同步
- **双人左右分区**：画面按肩中点 x 从左到右排序，玩家 1 = 画面左（青色），玩家 2 = 画面右（品红）

## 3. 功能需求

### 3.1 模式一：DJ 节奏（rhythm）

核心玩法：跟拍打点，冲击连击高分。

**赛制**

- 每局固定 90 秒，时间到进入结算屏
- 每局随机 BPM（112~128）与轮换曲风（HOUSE / EDM / FUNK 三种循环）
- 目标动作按 8 拍一循环轮换：左臂 → 右臂 → 左臂 → 双手 → 右臂 → 左臂 → 双手 → 下蹲（下蹲每 8 拍出现 1 次，防止过劳）

**判定规则**

| 等级 | 判定窗口（以目标拍时刻为中心） | 基础分 |
| --- | --- | --- |
| PERFECT | ±150ms | 100 |
| GOOD | ±300ms | 50 |
| MISS | 超出 ±300ms 未完成 | 0（断连击） |

- 窗口外完成的动作不奖不罚，等窗口结束统一记 MISS
- **连击加成**：当前连击数 ≥ 10 时，得分 ×1.5
- 每个目标的判定按玩家独立（双人互不干扰），单人/双人 HUD 分别显示分数与 COMBO

**评级（结算屏）**

| 评级 | 分数线 |
| --- | --- |
| S | ≥ 16000 |
| A | ≥ 10500 |
| B | ≥ 5000 |
| C | 其余 |

- 结算显示每名玩家：得分、最高连击、评级；并显示历史最高分（localStorage 键 `mwdj_best_v1`，双人取两人较高者入档，破纪录标"新纪录！"）
- 结算屏提供"再来一局"与"返回菜单"

### 3.2 模式二：乐器创作（instrument）

核心玩法：身体即乐器，动作直接映射乐器演奏。

**动作 → 乐器映射**

| 动作 | 乐器 | 规则 |
| --- | --- | --- |
| 左臂高举并挥动 | 钢琴 | 左腕高度映射 C 大调五声音阶 8 音（C4/D4/E4/G4/A4/C5/D5/E5），手越高音越高；冷却 200ms |
| 右手快速下压 | 吉他扫弦 | 右腕单帧下移超阈值触发，音高由触发时右腕高度决定：抬得越高音越高（E2~E4）；冷却 150ms |
| 双手高举 | 镲片 | 双手同举触发，冷却 500ms |
| 下蹲 | 和弦 | 每次下蹲按 C → F → G → Am 轮换演奏和弦并叠加底鼓；连续 3 帧确认 + 800ms 冷却 |

**录制与回放**

- 按 R 开始 8 秒录制（记录每个动作事件与时间戳）
- 8 秒到自动结束；录制中再按 R 立即结束并回放
- 回放可叠加：连续按 R 可多次触发回放，实现"一人乐队"
- HUD 实时显示录制状态（录制中 / 已录事件数）

### 3.3 模式三：自由舞台（free）

- 无评分、无判定、无 MISS：任何有效动作（左/右/双手/下蹲）都触发对应音效 + 灯光爆闪 + 中文鼓励语轮播
- 背景曲固定 110 BPM HOUSE，节拍驱动灯光律动
- 定位：热身、教学演示与低龄用户的安全游乐场

### 3.4 通用功能

- **单/双人切换**：菜单中选择，双人时感知层以 2 人模式运行、HUD 展示两列分数
- **画中画**：右下角小窗显示摄像头画面 + 实时 33 关节彩色骨架（P1 青 / P2 品红），点击收起/展开
- **动作引导弹窗**：每种模式首次进入时弹出大字号中文动作说明，确认后开始
- **键盘降级**：摄像头不可用/被拒/设备不支持时自动进入键盘模式，画面提示"摄像头不可用 · 键盘 J / K / L / I 照样玩"；无摄像头时同步显示 J/K/L 触屏按钮（移动端可点按）
- **全局快捷键**：ESC 返回菜单；R 创作模式录制/回放；D 开关调试面板
- **调试面板**：显示感知帧率/渲染帧率/检出人数/当前模式与状态/双方分数
- **结算与隐私**：DJ 模式结算入档历史最高分；全部数据仅存于本机浏览器

## 4. 非功能需求

### 4.1 性能

- **渲染目标 60fps**：全部动画基于 dt（帧率无关）；3D 人偶姿态插值按 60fps 基准校正
- **自适应降级**：平均 FPS < 30 持续 2 秒时自动逐级降级（先降阴影，再降粒子/LED 屏复杂度，最后关 Bloom），保证低端机可玩
- **感知节流**：姿态推理独立节流（单人约 35fps、双人约 25fps），与渲染帧率解耦，防止模型推理拖垮渲染
- **音频精度**：音序器采用 lookahead 调度（25ms 检查、提前 0.1s 精确排程），节奏不受页面抖动影响

### 4.2 兼容与降级

- 浏览器：Chrome / Edge 最新版（需 WebGL2 与 getUserMedia）
- 无摄像头 / 权限被拒 / 摄像头被占用 / file:// 打开：给出明确中文提示，自动进入键盘降级模式，核心玩法完整保留
- GPU 不可用：姿态识别自动降级 CPU 推理并提示用户
- 隐私模式（localStorage 不可写）：最高分读写全程容错，不影响游戏

### 4.3 隐私声明

- 摄像头画面与姿态数据**仅在本地浏览器内存中处理**，不经过任何网络上传、不落盘存储
- 姿态识别模型与 Three.js 库经 CDN 加载（只读下载），加载完成后推理全程端侧运行
- 页面关闭即一切画面数据消失；本地持久化的数据仅有一项——历史最高分（`mwdj_best_v1`）

### 4.4 可用性

- 全部用户可见文案为中文、不使用 emoji 滥用（仅菜单图标点缀）
- 中央判定文字使用 `aria-live="polite"`，辅助技术可感知
- 大字号、高对比、大按钮，兼容长辈与儿童操作

## 5. 技术约束

- 纯前端零构建：原生 ES Modules + importmap，仓库即产物
- 依赖版本锁定：three@0.160.0（unpkg CDN）、@mediapipe/tasks-vision@1.1.1（jsdelivr CDN）、pose_landmarker_lite 模型
- 无后端、无数据库、无用户账号体系

## 7. 验收标准

1. 三种模式均可在 Chrome 最新版正常进入并完整游玩一轮
2. DJ 模式判定窗口与计分符合第 3.1 节规则；90 秒准时结算并入档最高分
3. 断网状态下（首次模型缓存后）游戏本体可运行；无摄像头时键盘模式可完整游玩
4. 摄像头画面不出现在任何网络请求中（隐私红线）
5. Pages 部署后，<https://shixingya.github.io/motion-wave-dj/> 可直接游玩
